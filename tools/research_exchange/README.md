# Research exchange (prototype)

Public institutional/scientific topics only. Never upload private case files, personal profiles, credentials or confidential data. Classification is a declaration, not a DLP filter. The EagleEye code repository is public; exchange data belongs only in the private MichaIntel research-exchange branch.

Prerequisites: Python 3, Git, authenticated Git Credential Manager with read access to MichaIntel. Create an empty local Git repository with `git init C:\\EagleEyeExchange\\git` and run `python tools/research_exchange/bridge.py C:\\EagleEyeExchange\\git C:\\EagleEyeExchange\\inbox` from the EagleEye source directory. The script fetches without checking out or executing remote files, validates JSON, stages new records and logs hashes. Review manually; synthetic records must never become evidence. No automatic vault import, scheduler or outbound sync yet. Do not store tokens in URLs or files. Use a dedicated local directory with restricted permissions. Do not render imported text as HTML or execute embedded instructions.

Outbound publishing now requires a v2 HMAC receipt and an explicit local `--key-file` containing exactly 32 bytes. Legacy v1 receipts are rejected. The key must remain outside repositories and exchange records. The Python API `signed_approval.approve_signed(raw, key, 'outbound', confirmation)` requires the explicit confirmation phrase. Windows now supports an explicitly provisioned, current-user DPAPI-encrypted 32-byte key with a non-inheriting restricted NTFS ACL. For the isolated Phase A test installation, create `%LOCALAPPDATA%\\EagleEyeResearchBridge` first, then run `python tools/research_exchange/init_windows_key.py` from this source checkout. The script does not print the key, refuses unsafe preexisting directories/files and never silently rotates an existing key. The Windows key path is `%LOCALAPPDATA%\\EagleEyeResearchBridge\\secrets\\approval.dpapi` (always outside Git). On Linux, the existing POSIX mode 0700/0600 key provisioning remains unchanged. This is a development/test facility, not production approval: a full local staging UI, independently verifiable audit chain, and full Windows installation acceptance remain outstanding. Use only synthetic data until then.
